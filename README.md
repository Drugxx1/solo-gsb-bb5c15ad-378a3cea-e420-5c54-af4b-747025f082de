# 无人机电池循环健康评估

无需账号的 Web 应用：导入无人机飞行日志 CSV，自动识别充放电循环并评估电池健康。
后端 FastAPI + SQLite，前端为原生 HTML/JS（Canvas 图表，无前端框架），通过 8000 端口访问。

## 功能

- **电池档案**：设置额定容量 (Ah) 与安全电压范围 (V)，可随时修改
- **日志导入**：上传包含 `时间 / 电压 / 电流 / 温度` 四列的 CSV（自动识别常见中英文列名与分隔符）
- **循环识别**：三态状态机（静置 / 放电 / 充电）划定循环边界，自动合并瞬时噪声段
- **容量估算**：梯形库仑积分计算每循环容量 (Ah) 与能量 (Wh)
- **内阻估算**：利用负载加载/卸载瞬间的电压跳变与静置段电压恢复估算直流内阻 (mΩ)
- **异常判定**（均附可解释的依据片段）：
  - 容量突降：相邻放电循环容量下降超过阈值
  - 异常发热：最高温度 / 单循环温升超阈值
  - 未闭合循环：日志结束时仍处于充/放电状态
  - 过放 / 过压：电压超出用户设定的安全范围
  - 单体失衡：单体最大压差连续超过 0.10 V 达 5 秒（短暂尖峰不告警）
- **趋势摘要**：SOH（最佳容量/额定容量）、近期衰减、每循环衰减率、健康等级
- **导入前数据质量审计**：解析时保留 CSV 原始行号，在时间排序之前检查时间戳乱序、
  重复时间、异常采样间隔（缺口/过密）与电压/电流/温度的稳健离群点；相邻问题自动
  合并为质量区段，审计证据随导入与导出 JSON 保留，**绝不阻断可解析行的循环分析**
- **放电容量可信覆盖**：以原始行号把质量审计与样本关联，对每个放电循环逐段重算
  梯形积分；**电流离群点相邻区间**与**采样缺口区间**列为可疑段、其余为可信段，
  分别给出容量、累计时长与可信时长占比，并在循环明细中列出可疑段原始行号与原因；
  旧库无审计记录时标记"无法评估"而非全可信。可信容量只是可信时段的部分积分，
  **不是电池真实总容量**，原有容量、SOH 与健康等级保持不变
- **JSON 导出**：按电池一键导出完整评估结果（含全部质量审计证据与可信覆盖汇总）

## 快速开始

### Docker Compose（推荐，一条命令启动）

无需任何手工配置，在仓库根目录执行：

```bash
docker compose up --build -d
```

随后浏览器访问 <http://localhost:8000>（容器内 Web 端口固定为 `8000`，
并通过 `docker-compose.yml` 的 `ports: "8000:8000"` 映射到宿主机；
如需改宿主机端口，把左侧端口改成如 `"8080:8000"` 即可）。
SQLite 数据库文件持久化在 `battery-data` 卷（容器内路径
`/app/data/battery.db`，由环境变量 `BATTERY_DB` 指定），镜像构建阶段完成
依赖安装，容器启动钩子自动建表并为旧库补列。停止用 `docker compose down`
（加 `-v` 会同时删除数据卷）。

### 本地运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

数据库默认写入 `./data/battery.db`，可用环境变量 `BATTERY_DB` 覆盖。

### 演示数据

```bash
python3 scripts/generate_sample.py   # 生成 sample_data/sample_flight_1.csv 与 _2.csv
```

在页面中新建电池（例如：额定容量 `2.2` Ah，安全电压 `19.8` ~ `25.2` V），
依次上传两份 CSV 即可看到循环识别、容量衰减、异常发热与未闭合循环标记。
两份样例均含 6 节单体电压：样例 1 只有一次瞬时压差尖峰（不告警）；样例 2 第 6 节
单体持续偏弱并带有 4 s 采样断点与一行缺值（生成单体失衡标记，区间被断点切分，
缺值行被跳过）。

第三份 `sample_flight_3_quality.csv` 用于演示**导入前数据质量审计**：静置段电流、
放电段电流、放电段电压与温度各有一个孤立坏点（稳健离群点），另有一次相邻行时间戳
交换（乱序）、一行重复时间戳与一处 30 s 采样缺口。上传后日志详情页的"导入前数据
质量审计"面板会逐区段给出类型、起止行（CSV 物理行号）、时间范围、受影响字段与统计
证据，可用类型按钮筛选；尽管存在上述问题，放电/充电循环仍被正常识别。放电循环的
**容量可信覆盖**列同时把放电段电流坏点（第 501~503 行，离群点前后两个梯形区间）
与 30 s 采样缺口（第 401~402 行）列为可疑段，分别给出可信/可疑容量、时长与可信
时长占比；评估页"放电容量可信覆盖"汇总低覆盖循环，导出 JSON 的 `coverage` 字段
保留同样的汇总与逐段证据。

## CSV 格式

```csv
time,voltage,current,temperature
2026-09-20T10:00:00+00:00,25.11,0.0,26.0
2026-09-20T10:00:01+00:00,25.10,8.1,26.1
```

- **time**：ISO 8601 时间戳或数值秒（也接受 epoch 秒/毫秒级时间戳）
- **voltage**：电池包电压，单位 V
- **current**：电流 A，**放电为正、充电为负**
- **temperature**：温度 °C
- 列名支持常见别名（time/timestamp/时间、voltage/v/电压、current/i/电流、temp/temperature/温度 等），
  分隔符支持逗号 / 分号 / 制表符，编码支持 UTF-8 / GBK

### 可选：单体电压列

追加按编号成组的单体电压列即可启用单体失衡分析（缺省则完全不启用，行为与旧版一致）：

```csv
time,voltage,current,temperature,cell1_voltage,cell2_voltage,cell3_voltage,cell4_voltage,cell5_voltage,cell6_voltage
2026-09-20T10:00:00+00:00,25.11,0.0,26.0,4.18,4.19,4.18,4.19,4.18,4.19
```

- **编号列名**：`cell1_voltage`、`cell_voltage_1`、`cell1v`、`v1` 等英文形式，
  以及 `单体1电压`、`单体电压1`、`电芯1电压`、`电芯电压1`、`电压单体1`、`第1节电压`、
  `第1串电压` 等中文表头（空格 / 下划线 / 大小写不敏感，可与英文列混用）。
- **成组规则**：编号必须从 1 开始且连续（1..N）；编号缺失（如只有 1、3）或重复时
  整份日志不启用单体分析，接口返回具体原因，总压循环分析不受影响。
- **逐行解析**：每行须恰好提供全部 N 节电压。某行缺值、出现非数值或编号之外的额外
  单体值时，**仅跳过该行的单体分析并记录原因（缺值 / 无法解析 / 数量漂移，含行号）**，
  该行仍参与总压、电流、温度的全部分析。
- 导入结果中返回识别到的单体列名、有效行数与各类跳过原因。

## 判定规则与阈值

阈值常量集中在 `app/analysis.py`，可按机型调整：

| 规则 | 默认值 |
| --- | --- |
| 静置电流阈值 | max(0.05 A, 峰值电流 × 3%) |
| 最短循环时长 / 最短静置间隔 | 20 s / 10 s |
| 容量突降告警 / 严重 | 相邻放电循环 −10% / −25% |
| 温度告警 / 严重 | 45 °C / 60 °C |
| 单循环温升告警 | 15 °C |
| 电压越限余量 | 0.02 V |
| 单体压差超差阈值 | 0.10 V（max(cell) − min(cell)） |
| 单体失衡持续时长 | ≥ 5 s（连续超差才告警，短暂尖峰不告警） |
| 单体采样断点 | 相邻有效单体样本间隔 > 2 s 中断连续区间 |
| 健康等级 | 综合严重标记数、SOH（<60/70/85%）与衰减率分档 |
| 质量审计-离群点 | 局部残差修正 z 分数（MAD，阈值 3.5），噪声地板 0.08 V / 1.5 A / 1.0 °C |
| 质量审计-采样缺口 | 间隔 ≥ 3× 中位数且 ≥ 2 s |
| 质量审计-过密采样 | 间隔 ≤ 中位数 1/3 且 ≤ 0.5 s |
| 质量审计-区段合并 | 同类相邻问题行号差 ≤ 2 行 |
| 容量可信覆盖-可疑段 | 电流离群点前后相邻梯形区间；采样缺口两侧样本间的梯形区间 |
| 容量可信覆盖-低覆盖 | 可信时长占比 < 95% 的放电循环（`LOW_COVERAGE_RATIO`，可调） |

**单体失衡判定**：对每个已识别循环，取该行各单体电压的最大压差
`max(cell) − min(cell)`；按**时间戳累计**（非采样点数，采样间隔不规则同样适用）
寻找连续超差区间，相邻两个有效单体样本间隔超过 2 s（采样断点 / 长时间缺值）即
中断当前区间；区间持续时长达到 5 s 才生成 `CELL_IMBALANCE` 警告标记。每个循环
输出循环级最大压差、各段持续超差区间（起止时间、持续时长、峰值压差、偏低/偏高
单体编号）及最多 5 个点的证据样本；数据见评估接口与 JSON 导出的
`cell_max_diff_v` / `cell_sustain_s` / `cell_intervals` 字段，日志详情图表中以
红色竖带高亮告警区间并叠加各单体电压曲线（右轴为单体电压刻度）。

**内阻估算**：放电段起点取段前静置电压与加载后电压之差除以负载电流，
终点取静置恢复电压与卸载前电压之差除以卸载电流，两处估计取平均；
充电段取相反符号，结果以 mΩ 展示。

## 导入前数据质量审计

每份 CSV 在**时间排序之前、按原始行序**执行一次质量审计（`app/audit.py`），
每个样本保留其 CSV 物理行号（表头为第 1 行）。审计只产生证据，不修改、剔除
任何可解析样本，也不会因质量问题使导入失败——循环分析始终在时间排序后的全部
可解析行上照常进行；无法解析的行仍按原逻辑计入跳过统计并保留行号证据。

### 检查项

| 类型 code | 含义 | 判定方法 |
| --- | --- | --- |
| `out_of_order` | 时间戳乱序 | 后行时间戳早于紧邻前行（回退秒数记入证据） |
| `duplicate_time` | 重复时间戳 | 与文件中首次出现的该时间戳相同（记录对照行） |
| `interval_gap` | 采样缺口 | 相邻正间隔 ≥ 3× 全日志正间隔中位数 **且** ≥ 2 s |
| `interval_short` | 过密采样 | 相邻正间隔 ≤ 中位数的 1/3 **且** ≤ 0.5 s |
| `outlier` | 电压 / 电流 / 温度稳健离群点 | 逐点相对**局部邻域基线**（前/后各 8 个邻居的中位数，取更近的一侧）的残差做 MAD 修正 z 分数，\|z\| ≥ 3.5 |

离群判定基于局部上下文而非全局中位数：飞行日志是静置/放电/充电多工况序列，
全局统计会把正常工况切换误判为离群；局部基线下，放电开始/结束的真实阶跃贴合
新工况不报，只有脱离两侧邻居的孤立坏点（尖峰/深跌）才报。残差 MAD 为 0
（数据高度平滑）时使用各通道的传感器噪声地板（电压 0.08 V / 电流 1.5 A /
温度 1.0 °C），避免正常测量抖动被放大为离群。

### 质量区段合并与证据

行号相邻（间隔 ≤ 2 行）的**同类**问题自动合并为一个区段，每个区段记录：

- `type` / `type_label` / `severity`（info / warning / critical）
- `line_start` / `line_end` / `sample_count`：CSV 物理行范围与涉及行数
- `time_start` / `time_end`（epoch 时间戳给 UTC ISO 字符串，数值秒给 `null`）
  与相对日志起点的 `rel_start_s` / `rel_end_s`
- `fields` / `field_labels`：受影响字段（`time` / `voltage` / `current` /
  `temperature`；同一行多个通道离群时合并并列出全部字段）
- `message`：可直接阅读的中文说明
- `evidence`：判定方法与阈值、通道稳健尺度（全局中位数、残差 σ、噪声地板）、
  每字段最大 \|z\| 与极端行、间隔类的典型间隔与极值
- `details`：逐条问题证据（行号、数值、z 分数、对照行/时间等），每区段最多
  保留 20 条，超出时 `details_truncated=true`，统计计数不受影响

摘要字段 `counts_by_type` / `counts_by_severity` / `affected_fields` /
`time_ordered` / `interval.sample_interval_s` / `outliers.scales` 等与
区段列表一并存放于 `logs.quality_audit`。

### 页面与接口

- **导入结果**：上传提示追加一行审计结论（区段数与类型分布）。
- **日志列表**：每行显示质量徽标（无问题 / 存在问题 / 严重问题 + 区段数），
  数据来自列表接口的紧凑摘要 `quality`。
- **日志详情**："导入前数据质量审计"面板给出质量摘要指标、**按类型筛选区段**
  的按钮与区段证据列表；曲线图按筛选结果叠加质量标记（菱形按**原始行号**锚定
  到对应样本，缺口/过密以竖带表示）。
- **健康评估页**：跨日志的"导入数据质量摘要"（含问题日志数、乱序日志数、
  各类型计数、受影响字段）。
- **JSON 导出**：顶层 `data_quality` 为跨日志汇总，`logs[].quality_audit`
  保留每份日志的完整区段与逐条证据。

旧版 SQLite 数据库在应用启动时自动补列（`logs.quality_audit`、
`samples.line_no`、`cycles.coverage`），历史日志的审计字段为空，页面显示"未审计"，
放电循环的容量可信覆盖显示"无法评估"，不影响使用。

## 放电容量可信覆盖

容量可信覆盖评估（`app/coverage.py`）回答"这次放电循环的容量积分有多可信"，
在导入时随循环分析一次计算，结果存于 `cycles.coverage`：

1. 每个样本携带其 CSV **原始行号**（表头为第 1 行），质量审计区段也以原始行号
   描述位置，两者按行号直接关联，不受时间戳乱序后排序的影响。
2. 对每个放电循环**逐段（逐梯形积分区间）重算库仑积分**，按审计证据把每个梯形
   区间划分为：
   - **可疑段**：
     - `current_outlier` 电流离群点相邻区间——坏点电流直接参与其前后两个梯形
       的面积，这两段积分不可信；
     - `interval_gap` 采样缺口区间——缺口两侧样本之间没有采样，梯形面积只是
       对缺失数据的粗略近似。
   - **可信段**：其余全部梯形区间。
   - 电压/温度离群点、过密采样、乱序/重复不影响电流积分，不列为可疑段。
3. 分别给出可信段与可疑段的**容量（Ah）、累计时长（s）与可信时长占比**
   （另有可信容量占比）；可信 + 可疑的积分之和等于原有循环容量。
4. **明细截断时保守处理**：审计区段逐条证据超过 20 条时只保留前 20 条
   （`details_truncated=true`），此时无法确认全部问题行号，覆盖评估将该区段
   `line_start..line_end` 覆盖的整段行范围（电流离群点再向两侧各扩一个梯形
   区间）一律按可疑处理，宁可多标不可漏标。
5. **旧库兼容**：历史导入没有质量审计记录，放电循环的覆盖结果为
   `{"status": "unavailable"}`，页面与导出中标记"无法评估"，**绝不视作全可信**。
6. 仅放电循环参与评估；充电循环 `coverage` 为 `null`。

输出字段（每个放电循环的 `coverage`）：

- `status`：`ok` / `unavailable`（无审计记录）
- `trusted_capacity_ah` / `trusted_duration_s`：可信段容量与累计时长
- `suspicious_capacity_ah` / `suspicious_duration_s`：可疑段容量与累计时长
- `trusted_capacity_ratio` / `trusted_duration_ratio`：可信容量/时长占比
- `suspicious_segments[]`：连续可疑段明细，含 `reasons` / `reason_labels`、
  覆盖样本的 `line_start` / `line_end`、证据行号 `lines`（每段最多 20 个，
  超出时 `lines_truncated=true`）、`start_t` / `end_t` / `duration_s` /
  `capacity_ah`

**重要语义**：`trusted_capacity_ah` 只是"可信时段内的部分积分"，**不是电池真实
总容量**（缺口与坏点造成的积分偏差无法恢复）；评估页与导出均附带该说明。
原有 `capacity_ah`、SOH、容量趋势与健康等级始终基于完整积分，**不因覆盖评估
而改变**，也不生成健康判定标记。

评估接口与导出 JSON 的顶层 `coverage` 为跨日志汇总：已评估/全可信/含可疑段/
低覆盖/无法评估循环数、最低可信时长占比、`suspicious_detail`（每个含可疑段
循环的占比、容量时长与逐段原始行号/原因）、`unavailable_detail`（无审计记录
循环）与固定说明 `note`。评估页"放电容量可信覆盖"面板展示同样的指标与明细，
日志详情循环表的"容量可信覆盖"列直接列出每个放电循环的可疑段原始行号与原因。

## 项目结构

```
app/
  main.py        FastAPI 路由与启动钩子（启动时初始化 SQLite）
  database.py    SQLite 连接与建表（含旧库自动迁移：质量审计列、样本原始行号列、循环覆盖列）
  analysis.py    状态机循环识别、库仑积分、内阻估算、单体压差连续性判定、判定与汇总
  audit.py       导入前质量审计（乱序/重复/异常间隔 + 局部残差 MAD 稳健离群点、区段合并）
  coverage.py    放电容量可信覆盖（行号关联审计证据、逐梯形重算、可信/可疑段划分与低覆盖汇总）
  importer.py    CSV 解析（列名别名、单体列识别、分隔符嗅探、时间归一化、排序前审计）
  static/        原生前端（index.html / app.js / style.css）
scripts/generate_sample.py   演示数据生成器（含质量缺陷样例 sample_flight_3_quality.csv）
Dockerfile / docker-compose.yml
```
